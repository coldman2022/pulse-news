## Висновки для v25: переклад і поширення

- **[W3C Web Share API](https://github.com/w3c/web-share)** — найкращий варіант для Pulse PWA. Викликаємо `navigator.share({title,url})` без сторонніх SDK та без ключів; для браузерів без підтримки — `navigator.clipboard.writeText(url)` або ручне копіювання. Реалізовано у `static/share.js` та зворотних посиланнях у Pulse `?article=id` / `motivation.html?story=id`.
- **[Argos Translate](https://github.com/argosopentech/argos-translate)** — локальна офлайн-бібліотека Python, але для української потрібні мовні моделі, іноді опосередкований переклад через англійську та більше часу/ресурсів у GitHub Actions. Без кешу це буде накладно; варіант майбутнього пакетного експерименту.
- **[LibreTranslate](https://github.com/LibreTranslate/LibreTranslate)** — API на основі Argos; для стабільного використання потрібен власний сервер або керований план із ключем. Вставляти API-ключ у відкритий Pages JS не можна. Публічні інстанси можуть мати rate limits і блокування CORS.
- **[Linguist](https://github.com/translate-tools/linguist)** — браузерне розширення з Bergamot/локальними провайдерами, але не вбудовується як невелика готова бібліотека в iOS PWA. Корисне як дослідження UX, не як пряма залежність.
- **Рішення:** існуючий переклад заголовків на запит/у видимій частині через MyMemory лишається; спочатку спостерігати фактичну квоту та якість. Заміна перекладача — окремий етап із тестом української якості, мережевих лімітів, швидкості й приватності. Невірно називати безкоштовний публічний API гарантованим.

# Pulse — GitHub ideas backlog (28 жовтня 2026)

Мета: скоротити час перегляду новин, не втратити важливих сигналів, не додавати платний сервер без реальної потреби. Поточна архітектура: Python + GitHub Actions (годинна збірка), статичні файли на GitHub Pages, клієнтський JS, без власної БД.

## Найкраще для наступних версій без окремого сервера

1. **[Fuse.js](https://github.com/krisk/Fuse)** — швидкий нечіткий пошук у браузері, помилки в написанні, пріоритет заголовка над описом, підсвічування збігів. Практичний наступний крок: додати лише для пошуку, не змінюючи хронологічного порядку стрічки за замовчуванням.
2. **[RapidFuzz](https://github.com/rapidfuzz/RapidFuzz)** — порівняння схожих заголовків на етапі Python-збірки; об'єднувати повторні матеріали за одним сюжетом з окремими посиланнями на джерела, але не плутати різні події зі схожими заголовками. Для різних мов потрібен окремий підхід.
3. **[RSS-Bridge](https://github.com/RSS-Bridge/rss-bridge)** та **[RSS Funnel](https://github.com/shouya/rss-funnel)** — приклади роботи з RSS-сайтами без офіційних фідів, фільтрація ключовими словами та об'єднання джерел. RSS-Bridge потребує PHP-хостингу, RSS Funnel — окремого процесу; логіку можна частково повторити у власному Python-парсері без запуску цих сервісів.
4. **[Newspaper4k](https://github.com/AndyTheFactory/newspaper4k)** та **[Trafilatura](https://github.com/adbar/trafilatura)** — текст і метадані з оригінальних сторінок, у Newspaper4k — `top_image` і `meta_img`. Для картинок порядок: (а) офіційний RSS media:thumbnail/enclosure, (б) `og:image` або `twitter:image` на сторінці видавця, (в) залишити статтю без фото. Не підставляти випадкові результати пошуку за заголовком. Потрібні обмеження запитів і контроль прав на медіа.
5. **[rss-digest](https://github.com/bkubinszky/rss-digest)** — ранжування та коротка добірка через GitHub Actions. Корисна структура для персональної ранкової підбірки без власного сервера, але використання AI API може коштувати грошей.

## Ідеї, що потребують значної зміни інфраструктури

- **[Cruxwire](https://github.com/philoking/cruxwire)** — локальний Ollama для персонального скорингу, схожих історій, короткого змісту. Варто запозичити логіку відбору, а не переносити весь стек на Pages.
- **[Better News](https://github.com/sxntixgo/betternews)** — лайки/дизлайки, персоналізований рейтинг, «що пропустив», офлайн-читання. Потрібні додаткові процеси й сховище.
- **[Jadro](https://github.com/MatejGadjo/jadro)** — мультимовне групування новин у сюжети (embeddings, pgvector). Дорожчий стек; поки достатньо легшої кластеризації.
- **[NewsFeed](https://github.com/cipriangheorghite/newsfeed-public)** — багатоджерельна стрічка, читання статей, live-оновлення та PWA; серверний застосунок, не вставляється напряму в Pages.
- **[LibreTranslate](https://github.com/LibreTranslate/LibreTranslate)** / **[Argos Translate](https://github.com/argosopentech/argos-translate)** — власний сервер чи пакетне офлайн-перекладання, без залежності від браузерного MyMemory, але з витратами ресурсів та додатковим налаштуванням.

## Пропонований порядок

**Етап 1 — швидко та без постійного сервера:** Fuse.js + покращення читабельності/сортування + безпечне джерельне зображення `og:image` там, де RSS не дав фото. Зберегти повну URL-атрибуцію.

**Етап 2 — економія часу:** групування однакових сюжетів, пріоритет «для мене» і розумне виявлення вже прочитаного. На головній одна картка сюжету + кілька першоджерел.

**Етап 3 — за результатами тесту:** точні підсумки зі збереженням посилань на джерела; пакетний переклад лише потрібних матеріалів; сервер/AI — лише якщо дійсно дають відчутну користь.

## Обмеження та перевірки

- Не називати дописи Reddit перевіреними новинами; RSS не дає аналізу коментарів.
- Не зберігати й не видавати випадкові сторонні зображення як ілюстрацію конкретної події.
- Перевірити ліцензії, robots.txt, частоту запитів та правила джерел перед інтеграцією.
- Не публікувати API-ключі в GitHub Pages чи клієнтському JS.
- Синхронізація збережених новин між телефонами потребуватиме окремого сховища/авторизації; наразі стан прив'язаний до браузера.
